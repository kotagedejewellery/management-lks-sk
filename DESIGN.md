# Dashboard reporting

## Typography and product identity

The application uses **Manrope** as its only web UI typeface. Heading, navigation, form, data, and metric hierarchy comes from the existing size and weight scale (400â€“800), not from a second display font. Authentication and document-verification pages follow the same rule. PDF generation uses its built-in **DejaVu Sans** consistently; it stays self-contained and avoids remote-font rendering changes that could break the one-page LKS layout.

## Authentication

The login page is a calm, task-first entry point: the supporting panel carries the daily-recording message while the form begins directly with **Masuk ke LKS**, without assuming that every user has a temporary password. The form keeps one clear action, puts account-admin guidance beside that action, and presents field-specific validation with a textual error and an accessible invalid state. The desktop LKS lockup uses a 48 px mark with a 19 px product name and 12 px supporting label so it remains proportional to the introductory headline; on narrow screens it returns to a compact 34 px mark. The supporting panel collapses to that lockup so entering an account remains the only task in view.

For an active Santri Karya account, Admin can choose **Atur ulang password** directly from its row. The focused dialog asks for a new temporary password and its confirmation, states that existing sessions end and a password change is required on next entry, then asks for one deliberate confirmation before saving. Password creation, reset, and self-service change follow the same security policy. The action is unavailable unless both stored account statuses are active, whose recovery path is to reactivate the account first. The management form shows the latest reset's administrator and time as read-only context. On phones, the three row actions move into a full-width action row so each remains readable and tappable.

When an activity is being saved, its quick and detailed checklist controls share one pending state for that activity and date, including after a dashboard rerender. Both controls become unavailable and state **Menyimpan…** until the server response supplies the final completion state. A newer date selection always wins over a pending save response; validation feedback states the specific rule that blocked recording and remains beside the affected activity.

The sidebar mark is followed by **LKS** and the supporting label **Lembar Kendali Spiritual** on desktop. The compact mobile lockup remains only the mark and LKS. The personal recording navigation is named **Aktivitas Ibadah Saya**; established terms such as LKS period, LKS history, and report scope remain unchanged.

Dashboard Admin keeps programme health readable before comparison. A single **Jenis LKS** selector scopes the summary, department bars, and follow-up link together: Semua jenis LKS, Reguler, or Magang.

The selector is a normal labelled control, uses the existing paper-and-evergreen system, and expands to the available width on mobile. Rekap makes the active passing rule explicit: Leader 90%, Staff Reguler 85%, or Staff Magang 75% by default. Activity targets remain independently configured per category.

Aktivitas & Aturan tetap memakai satu aktivitas master agar riwayat dan pemakaian periode tidak terpecah. Formulir tambah menampilkan section **Aturan Reguler** dan **Aturan Magang** secara berdampingan pada desktop dan berurutan pada ponsel; masing-masing memuat target, batas mingguan, jadwal, sasaran, status aktif, dan dispensasi Akhwat miliknya sendiri. Aturan Magang hanya memilih jenis kelamin karena seluruh Magang berlaku sebagai Staff. Dari daftar, **Edit default Reguler** atau **Edit default Magang** membuka satu form terisi untuk kategori yang dipilih, sedangkan **Kelola kode & nama** hanya mengubah identitas aktivitas. Kode menjadi baca-saja setelah aktivitas dipakai periode, dengan penjelasan singkat; nama tetap dapat diperbarui. Kolom Status selalu mengikuti kategori yang sedang dipilih, dan target minimal langsung dibatasi oleh target maksimum. Ringkasan periode menghitung aktivitas aktif bila salah satu kategori aktif dan menjelaskan kategori aktifnya. Snapshot lama yang belum memasukkan Staff untuk Magang diberi catatan tanpa mengubah nilainya. Snapshot periode aktif atau tertutup tidak berubah saat default diedit.

Dashboard Santri names the active LKS category beside the current score. Dashboard Leader keeps one team view: it states the current Reguler/Magang composition and names each member's category in the attention list and achievement rows. It does not add a separate filter or a second dashboard, so follow-up still begins from one complete team view.

The amber daily reminder appears only when no applicable activity has been recorded that day; partial progress remains ordinary progress. Riwayat loads only the selected year, shows an authorized annual statement for a Santri or Leader team, and offers an accessible **Unduh CSV** action for that same scope. Dashboard Admin adds a year-selectable organization statement for final periods, with weighted average, clearly labelled participant-period completion accumulations, **Unduh CSV**, and a direct route into the existing Recap; the active-period summary remains visibly temporary. In Data Santri Karya, a missing employment start date is named in text and exposed only when needed as a labelled data-completeness filter with its count; the edit form updates the computed Magang/Reguler guidance before it is saved.

Individual rankings appear only in the Ikhwan/Akhwat report and only for Staff. The report presents up to three highest and three lowest Staff separately for Ikhwan and Akhwat; a participant is not repeated between a gender's two lists when that gender has fewer than six Staff. Leader, department, and LKS-category tabs use comparative group bars and trends without ranking cards; each ranked Staff row names its LKS category in text.

The Department trend selector contains every active department, plus historical departments preserved by snapshots within the six periods rendered in the chart. Active departments use their current master name; archived departments retain their historical snapshot name. A department with no participants in a given period remains selectable and renders that period as **—**, rather than a misleading 0%.

The Admin department report renders all departments together in a six-period comparison table ending at the selected report period, with a compact bar for each value; its horizontally scrollable layout preserves the full comparison on narrow screens and announces that it can be horizontally scrolled. Under it, an Admin-only follow-up card is shown for each department in the selected report period. A department with no participants is explicitly not rated. When every member is tuntas, the card gives a short reinforcement without naming people. Otherwise it lists at most three members with the largest gap to their own threshold, together with no more than two activities needing attention; this is a follow-up aid, never a statement that an individual caused the department score, and it is excluded from PDFs and non-Admin views. Every drill-down preserves the selected report period, and a failed trend request is stated as a loading error rather than being presented as missing historical data.

Leader, Ikhwan dan Akhwat, and Jenis LKS use the same all-group six-period comparison pattern ending at the selected report period. Gender and LKS category keep their natural two-row order; Leader is alphabetical. Each value names its participant count, and **—** means the group had no participants in that period. The report introduction avoids implementation terms: active periods say that the score is temporary up to today, while closed periods say that the displayed result is final.

Recommendations use a warm, neutral second-person voice: acknowledge progress first when appropriate, state the score or remaining gap, then name no more than two activities for follow-up. When individual minimums are met but the final threshold is still missed, the two lowest activities provide that follow-up. The copy avoids automatic gendered salutations and blame. The same plain-text recommendation is used on the dashboard, recap, history, and PDF; closed periods preserve it as a snapshot.

PDF actions use a labelled preview step before download. On desktop, the preview opens in a keyboard-operable dialog, keeps the document in the current task, provides a clear close action and a single primary **Unduh PDF** action, and retains a short fallback message for browsers that cannot render PDF inline. On narrow mobile viewports, the same authorized PDF opens in the browser's native viewer instead of an iframe, with browser back navigation returning to LKS. A non-PDF response is treated as an error; an expired session tells the user to sign in again.

The individual LKS PDF header keeps the full Yayasan Riyadhul Jannah Indonesia logo on the left and the full Kotagede Jewellery logo on the right. The centered title uses two balanced lines—**Lembar Kendali Spiritual** and **Santri Karya PT. Kotagede Jewellery Group**—followed by **Yayasan Riyadhul Jannah Indonesia** on one smaller line. The period remains in the identity block so the compact header does not push the document past one A4 page. Closed-period documents repeat the same verification QR above each of the first two officials' names; both codes resolve to the single immutable document-verification record.

An active period has an explicit recording state: **Dibuka** or **Dijeda**. Admins control it from the period detail alongside, but distinct from, the irreversible **Tutup periode** action; the period list repeats that substatus. When recording is paused or the date range has ended, Santri retain a read-only view of their records with a direct explanatory message on every unavailable checklist item; checklist and bulk actions are unavailable.

When a participant joins an active period after its start, the date control and bulk checklist begin at their participation date. A concise note states that their target is calculated from that date, without adding a separate configuration step.

For Akhwat, the date rail provides **Kelola dispensasi menstruasi** in a focused private dialog. The form records one past-or-current date range and lists only that participant's existing ranges with a deliberate delete action. An affected activity remains visible but its checklist control is unavailable and labelled **Dispensasi tercatat**; daily progress excludes it and makes clear when all activities are exempt. The UI never implies an automatic completion or exposes the dates in recap, Leader, department, or PDF views. In the private Admin checklist-correction dialog, Admin may add or remove the same participant's dispensations and must supply an audit reason.

On an active period's participant roster, search is paired with compact Departemen, Tim, status checklist, and Jenis LKS filters. Tim remains unavailable until its Departemen is chosen; all filtering and the existing pagination run on the server. The controls wrap into two columns and then one on narrow phones, with a visible Reset filter action only when a filter is active.

Rekap and the Leader dashboard append **Mulai [tanggal]** only for members who joined after the period started, so a new member's partial-period score is not mistaken for a full-period score.

Every rekap period selector retains all periods available to its current role and scope: an active period first, followed by closed periods from newest to oldest. Native option groups distinguish **Periode aktif** from **Riwayat periode**. Choosing a closed period never removes the active period from that selector; if a selected period becomes unavailable, the view returns to the newest allowed period with an explanation.

Period detail groups its three completion thresholds under one **Ambang tuntas** block. On phones, the block spans a full grid row and the recording controls may wrap rather than overflow. The reversible recording action is a distinct secondary control, while **Tutup periode** remains visually separated as the irreversible action.
